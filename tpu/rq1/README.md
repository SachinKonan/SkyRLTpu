# RQ1: how should we collect N samples on a code-optimization problem?

Agents/models NEVER touch our grader. Every prompt states the seed program + its PRODUCTION
score + direction. All grading happens afterwards, offline (`server/grade_batch.py`).

## Run matrix (per problem)

| Cell | What | N | Runs on |
|---|---|---|---|
| B | independent `codex exec` rollouts, gpt-5.6-sol xhigh | 200 | **Meta devserver** |
| C | completions, Qwen3.5-27B (think + code, temp 1.0) | 200 | neuronic -> farm |
| D | completions, gemma4-31b | 200 | neuronic -> farm |
| C/D | mixed 100+100 (analysis-only resample) | — | `analyze.py --mix` |
| E | sol-xhigh orchestrator, multi_agent_v2, 100 sol subagents (<=25 conc) | 100 | **Meta devserver** |
| F | sol-xhigh orchestrator + `sample_farm` MCP tool -> best T2 config | 100 | neuronic |

Placement rule: Meta devserver = full-agent cells only (B, E). Anything touching the OSS farm
(C, D, F) stays on neuronic. E vs F is the matched head-to-head (same orchestrator + budget,
draw type differs).

Problems: `fc46` (job-shop C++, shakedown first), `erdos`, `ac1`, `ud` (unit-distance, N=65536).

## Layout

- `client/` — **portable**: needs only `uv` + the codex CLI (+ farm URL for C/D/F). No repo
  imports; each script is PEP 723 (`uv run <script>.py`). `client/data/<problem>/` packs are
  generated by the server side and committed so the devserver clone has them.
- `server/` — neuronic-only (discover venv + trees by absolute path): pack builder, batch
  grader, analysis.
- `jobs/` — sbatch wrappers (never run compute on the login node).

## Order of operations

1. **Packs** (neuronic): `sbatch jobs/build_packs.sh` — grades each seed at production budget,
   stamps the score into both prompts (asserted). Commit `client/data/`.
2. **Local shakedown** (neuronic): `sbatch --nodelist=neu332 jobs/collect_t1_neuronic.sh fc46
   ../../runs/rq1/fc46_smoke 3 3`, then `sbatch jobs/grade.sh fc46 <that dir>` — 3 rollouts ->
   3 submissions -> 3 scores proves pool/capture/grading end-to-end.
3. **Devserver** (Meta): clone the `rq1-collection` branch (or scp `tpu/rq1/client/`), then
   - `uv run preflight.py` (checks codex, sandbox mode, g++, stream; recommends `--site`)
   - cell B: `uv run collect_t1.py --problem fc46 --n 200 --model gpt-5.6-sol --effort xhigh
     --site auto --out runs/fc46_B`
   - cell E: `uv run orchestrate_t3.py --arm E --problem fc46 --budget 100 --concurrency 25
     --out runs/fc46_E`
   - sync back the whole `runs/` dir (rsync/scp/git); grading consumes it as-is.
4. **Farm** (our GCP TPUs, managed from neuronic): 2x v5p-16 via the MAIN checkout's proven
   envs `tpu/runs/qwen35-27b.env` + `tpu/runs/gemma4-31b.env` with `START_TINKER=0`,
   `VLLM_MAX_MODEL_LEN=32768`, vLLM `--api-key`. Reach it via SSH tunnel
   (`tpu/tunnel_tinker_api.sh` pattern -> `http://127.0.0.1:<port>`).
   - cell C/D: `uv run collect_t2.py --problem fc46 --n 200 --farm-url ... --model ... --out
     runs/fc46_C --resume` (safe across preemptions)
   - cell F: `uv run orchestrate_t3.py --arm F --problem fc46 --farm-url ... --farm-model ...
     --out runs/fc46_F`
5. **Grade + analyze** (neuronic): `sbatch jobs/grade.sh <problem> <run_dir>` per cell, then
   `python3 server/analyze.py --results runs/fc46_*/result.json
   --mix CD=runs/fc46_C/result.json,runs/fc46_D/result.json`.

## Contracts

Run dir: `submissions.jsonl` ({session, agent_key, sol_hash, approach, insight, source}),
`solutions/<hash>.txt`, `manifest.json`, per-rollout `r*/events.jsonl`, T2 `raw/` (FULL think+
text — never discard raw generations), `result.json` after grading.

Capture MCP: `submit()` once per agent (keyed on the transport `mcp-session-id`, unforgeable);
salvage fallback mines `-o` final messages into the same jsonl with `source=salvage`.

## Hard-won site notes (encoded in `preflight.py`)

- neuronic: `use_legacy_landlock` (user namespaces disabled -> bwrap dies), `openai-long`
  provider (stream idle drops), avoid neu301 (egress), codex at `~/.npm-global/bin`.
- Config keys MUST go in `config.toml` (validated by `--strict-config`); `-c` silently drops
  invalid keys.
- multi_agent_v2: defaults hide spawn_agent's model args and cap threads at 4 including root
  (openai/codex#31814) — both overridden in the E-arm CODEX_HOME.
