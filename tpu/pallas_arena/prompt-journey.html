The honesty invariant

Four of the five baselines are labelled fallbacks, not production kernels.

Every headline number on this page is a ratio against a denominator, and for four of the five tasks that denominator is an honest fallback the judge falls back to because the real production kernel refused our shapes or was never bound:

Part I · The journey

Where the prompts started, and every step that moved a number

The arena grades whole programs on real silicon: a candidate must trace at every declared shape, compile under a 90-second budget, be numerically correct on hidden seeds, be bitwise deterministic, and then be timed against a baseline. Nothing about the prompt matters until a candidate clears all of that.

The measurement that drives everything below is not the pass rate. ttt-discover normalizes advantage within a group of rollouts, so a cell where every candidate scores identically contributes exactly zero gradient however good it looks. The metric is the fraction of complete 16-candidate groups whose reward spread exceeds the judge's own measured noise floor. That distinction produced the first real finding, before any prompt was improved at all.

Prologue 3650240 / 3650988 / 3686851 3 all-zero grids

Three grids of zeros that had nothing to do with the model

Before any prompt lesson is trustworthy, this one is: an all-zero grid is a harness alarm until proven otherwise. Three separate confident zero-grids in this arena were caused by infrastructure:

  • A token budget that truncated everything. At MAX_NEW_TOKENS=6144 the first 48 generations across both models and both tasks came back finish_reason="length" — 48 of 48 — and 0 of 48 survived the pre-gate. The whole budget went into the thinking channel; the extractor picked up partial sketches quoted mid-thought, so the modal gate was ast: syntax error: unexpected indent. Median extracted program: 1,108 characters against ~17,000 characters of generation.
  • A signature-tuple bug. probe_signatures() returns a 4-tuple; the driver handed the whole tuple to the export child, which then evaluated sig["args"] on a list. 14 of 32 candidates died with the byte-identical message TypeError: list indices must be integers or slices, not str — and it destroyed exactly the candidates well-formed enough to reach export.
  • Engines that were not serving. A spot preemption five minutes into generation left 640 of 672 rows as error:URLError(ConnectionRefused) with gen_chars=0. A later run lost a complete 31-minute bring-up to a transient GitHub fetch for causal-conv1d, a package nothing in the run uses.

Each one produced a table that read like "no model can write a Pallas kernel". The guards that came out of them — a hard pre-flight completion per engine, mid-run liveness checks, a no_code alarm at 30% per config, and a pre-warm that builds the entire grid environment before a single chip is provisioned — are now the reason the later numbers can be read at all.

Run 1 · cold start job 3650240 · 08-07 186 candidates
2 tasks · 2 models

Can a base model write a Pallas kernel at all?

Three strictly-nested prompt variants per task, so any arm-to-arm difference is attributable to the added block alone:

  • minimal — task spec, signature, declared shapes, judge contract. Nothing else.
  • reference — plus the public fp32 oracle inline (labelled as the correctness oracle and as an invalid answer), plus a ten-item Pallas/Mosaic gotcha list in prose.
  • tailored — plus a working scaffold in which every structural decision is given and exactly one function is left blank.

Two results defined everything after.

Prose cannot teach a function signature. On splash, gemma finished 14–16 of 16 generations and wrote a genuine pallas_call — then invented its keyword arguments. The reference arm's ten-item gotcha list did not move that number by a single candidate: 0/16 export, twice.

Run 2 · the seam job 3651278 · 08-07 160 candidates
5 tasks · 2 models

Give away the plumbing, keep the decisions

If prose cannot teach a signature, hand the signature over. The seam prompt gives the model the entire pallas_call — grid, every BlockSpec, every index map, the padding and un-padding — verbatim, as the exact scaffold its answer will be pasted above. The model writes only named fill functions. What it does not give away is every choice that moves the number: block and tile sizes, key chunking, which blocks to skip, online versus two-pass softmax, accumulation dtype, matmul precision.

On its target failure it worked decisively.

More important than the rates, the failure modes moved wholesale. reference fails at "I do not know this library's API". The seam fails at "I wrote the wrong thing into a Ref" — 'MemoryRef' object does not support item assignment, Invalid shape for swap. Ref shape: (8, 4, 128), too many values to unpack (expected 2). Where it failed is equally informative: on GMM and RPA, the seam's own interface became the difficulty. An 8-argument decode_block with two persistent scratch Refs produced its own modal error, and both tasks stayed at 0/16.

Run 3 · the ladder job 3687041 · 08-12 480 candidates
5 kernels × 3 rungs × 32

Four rungs, one variable each, on whole-program prompts

A strict superset ladder over a fixed BASE (task spec, exact signature, declared shapes including the non-divisible holdout, judge contract, fp32 oracle):

  • P1 — the DIALECT list. Ten bullets, each carrying the verbatim error string it eliminates and the number of candidates in the previous run that died on it. Nothing general: a bullet with no measured victims does not earn its tokens.
  • P3 — typed skeleton + one complete worked example. The arena's own RMSNorm golden, which passes this judge on silicon. Pins the API by demonstration rather than description.
  • P4 — primitives (dot_f32, iota2, fill_ref, online_softmax, chunk_scan), prepended and optional — except for FLCE, which instead gets the backward contract stated exactly, because its failure is mathematical rather than structural.

The dialect list was the big win. Across all 480 candidates no_code went to 0/480, and it removed the in-kernel Ref-semantics class outright: 'MemoryRef' object does not support item assignment 7 → 0, Invalid shape for swap 7 → 0, custom_vjp def_fwd 1 → 0.

The worked example backfired, measurably. It removed splash's invented pallas_call kwargs (10 → 0) — the example taught the real signature — and replaced them with a new failure in 60 candidates:

The failure the worked example introduced
Block shape for args[0] (= (Blocked(128), Blocked(128))) must have
the same number of dimensions as the array shape (8, 4096, 128)

The example was a fused RMSNorm over a [rows, cols] array, so it demonstrated a 2-D BlockSpec; models copied that rank onto splash's [heads, seq, head_dim]. A worked example transfers its shape assumptions along with its dialect. That is the single most useful negative result in the project.

Run 4 · seam + dialect job 3687904 · 08-12 224 candidates

The two things that ever worked, combined

The seam is the only variant that has ever exported splash. The dialect list is the only prompt addition ever measured to remove a failure class cleanly — and two of the classes it removes are the seam's own modal failures. So: seam plus dialect, no more prose. Two arms, sd1 (seam + dialect) and sd2 (sd1 plus a typed skeleton of the fill functions at the task's own rank — deliberately no foreign worked example, because rank transfer is what broke P3).

One measurement was cleaned up first. Seventeen of GMM's ladder failures were ValueError: Unsupported TPU device kind: cpu, which is not a statement about a kernel: every one of those candidates wrote a rank-1 BlockSpec, and Pallas's rank-1 block-shape check asks the current device for its sublane and lane geometry, which under JAX_PLATFORMS=cpu raises before the check can run. Pinning the device kind during export rescued 11 of the 17 outright; the other 6 now fail on a legible model error instead of on the harness's hostname.

The rule that came out of it

Prose helps exactly one class of problem: the one that is about mathematics you can state. For the class that is about interface plumbing you must write, prose, worked examples and primitives all fail — and a worked example can actively hurt by transferring its own shape assumptions. The lever that works on those kernels is structural: give the model the pallas_call, and tell it only the mistakes that have real victims.

Diagnosis · the change in flight

bf16 in, float32 accumulate — as a directive, not a trade

Every reference in the arena computes in float32. On TPU, jax.lax.dot_general on float32 operands runs one bfloat16 pass at the default precision — so a candidate that writes the obvious matmul is quietly computing at half the reference's precision and lands just outside a tolerance calibrated against float32. The dialect list already names this, but names it as a choice: "The choice is yours."

The change in flight is to make preferred_element_type=jnp.float32 — bf16 inputs, f32 accumulator — a directive, and to say explicitly that Precision.HIGHEST is not the answer. HIGHEST is roughly 6× the passes; teaching a model to win correctness by being slow would corrupt the only signal the arena has. bf16-in / f32-accumulate is also what every production kernel this arena benchmarks against actually does — Google's splash, vLLM's paged attention, MaxText's megablox, and our own FLCE.

Supporting evidence already in the record: the arena's own splash control kernel missed tolerance by 18% (max error 4.11e-3 against a 3.48e-3 budget) for exactly this reason and nothing else; the winning GMM and splash kernels both call dot_general with preferred_element_type=jnp.float32; and the one working RPA kernel uses Precision.HIGHEST throughout, which is very likely why it is correct and 2.6× slower than the fallback it is scored against. This change has not yet been measured — it is a hypothesis with converging evidence, not a result.

Part III · Per-kernel reference

The five kernels: contract, golden truth, unit test, prompt

Each task module declares a signature contract in its docstring, an fp32 closed-form reference() that is the correctness oracle, a baseline() that is the score denominator, and an adversarial vector library — the cheater battery — designed so that every known way of faking correctness has a test it must fail.

Shared by all five

Tolerance is calibrated, never fixed. The judge runs the reference at bf16 working precision, measures the per-element error |cand − ref| / (|ref| + 1) on both the max and the 99th-percentile tail, and sets the candidate's budget at TOL_MULTIPLIER = 1.5 times that, floored at 1e-6. The mechanism (calibrated_tolerance) takes the worst spread across reference_bf16 plus any honest_variants(), so an honest kernel with a different-but-valid numeric path is never rejected — but in practice none of the five arena kernels overrides honest_variants() (only the RMSNorm warm-up does), so their tolerance is 1.5× reference_bf16 alone. rg_lru and flce instead supply task-specific reference_bf16 overrides, which is where their calibration nuance lives.

Golden truth

causal_segment_attention upcasts q, k and v to float32, forms the full logits with an einsum, and masks to causal AND equal-segment AND both-sides-live using a large finite negative constant (−0.7 × float32max, never −inf, because −inf − −inf is NaN). It then does a max-shifted softmax and, critically, forces fully-masked rows to exactly 0.0 rather than NaN. There is no 1/sqrt(head_dim) scale — make_inputs pre-scales q, and this is stated in the prompt so the arm is not secretly measuring "did you guess the scaling convention".

Cheater battery

  • softmax-saturating — q × 300; output must stay finite.
  • fully-masked-rows — every 5th row set to segment 0; those rows must be exactly 0, checked with abs(out[:, dead, :]).max() == 0.0.
  • outlier-value-rows — one v row set to 3e4.
  • near-overflow-bf16-keys — one k row set to 1e4.
  • Banned: jax.nn.dot_product_attention, jax.nn.scaled_dot_product_attention, and the whole jax.experimental.pallas.ops tree that holds the reference splash kernel.

def choose_blocks(seq, head_dim):
    """bq=128 allows for efficient tiling on TPU sublanes and fits the score
    matrix (128 x 4096 f32 = 2MB) well within the VMEM limit."""
    return 128, 128

def attn_block(q_ref, k_ref, v_ref, sq_ref, sk_ref, o_ref, *, bq, bk, kv_len):
    q_val = q_ref[0]                      # (bq, dp)
    k_val = k_ref[0]                      # (kv_len, dp)
    v_val = v_ref[0]                      # (kv_len, dp)
    seg_q = sq_ref[:, 0]                  # (bq,)
    seg_k = sk_ref[0, :]                  # (kv_len,)

    logits = jax.lax.dot_general(
        q_val, k_val, (((1,), (1,)), ((), ())),
        preferred_element_type=jnp.float32)          # (bq, kv_len)

    q_block_idx = pl.program_id(1)
    global_q = q_block_idx * bq + jax.lax.broadcasted_iota(jnp.int32, (bq,), 0)
    global_k = jax.lax.broadcasted_iota(jnp.int32, (kv_len,), 0)
    causal_mask = global_q[:, None] >= global_k[None, :]
    seg_mask = (seg_q[:, None] == seg_k[None, :]) & (seg_q[:, None] != 0)
    mask = causal_mask & seg_mask

    NEG_INF = -1e30
    masked_logits = jnp.where(mask, logits, NEG_INF)
    row_max = jnp.max(masked_logits, axis=-1, keepdims=True)
    p = jnp.exp(masked_logits - row_max)
    p = jnp.where(mask, p, 0.0)
    denom = jnp.sum(p, axis=-1, keepdims=True)
    row_live = jnp.any(mask, axis=-1, keepdims=True)
    p = jnp.where(row_live, p / jnp.maximum(denom, 1e-30), 0.0)

    out = jax.lax.dot_general(
        p, v_val, (((1,), (0,)), ((), ())),
        preferred_element_type=jnp.float32)          # (bq, dp)
    o_ref[...] = out[None, :, :]

A two-pass, whole-key-axis softmax at bq=128. The model reasoned explicitly about the 2 MB score tile against the ~32 MB VMEM ceiling and concluded it did not need to block the key axis or skip anything — it ignores the bk it returned. That is exactly the kind of strategy decision the seam exists to leave open, and the trade is visible in the score: 4.6× at seq=4096, only 1.14× at the non-divisible holdout.

Best result, with its caveat

3/32 PASS, 15/32 export, best reward 3.2456 — 4.6× the xla-fallback denominator, not Google's splash kernel, which refused these shapes. PASS-only spread 0.0415 against a 0.0300 floor: it clears, but on 3 passing candidates that is a weak measurement, and the 108× whole-group spread is mostly the 29 zeros.

Golden truth

jax.lax.ragged_dot with both operands cast to float32 — the design floor, itself cross-checked in the CPU battery against an independent numpy loop that walks the groups row by row. Crucially, group_sizes are re-sampled per grading from both a uniform and a Zipf-skewed distribution, so a kernel tuned for one imbalance profile cannot fake a win.

Cheater battery

  • empty-expert-groups — sizes [0, m/2, 0, m−m/2]; output must stay finite. Skipping a zero-size group must not shift the row offsets.
  • max-skew-single-expert — all m rows in group 0, and the result is checked exactly against lhs @ rhs[0] at rtol/atol 2e-4.

def gmm_tile(l_ref, r_ref, o_ref, *, bm, bk, bn, k):
    """
    Performs one grid step: [bm, k] @ [k, bn] -> [bm, bn].
    """
    lhs = l_ref[...]          # (bm, k)
    rhs = r_ref[0, ...]       # (k, bn)
    res = jax.lax.dot_general(
        lhs,
        rhs,
        (((1,), (0,)), ((), ())),
        preferred_element_type=jnp.float32
    )
    o_ref[...] = res

Golden truth

paged_decode_attention_reference gathers the pages named by page_tables into a dense [b, max_len, kv_heads, d] tensor, upcasts to float32, and runs an ordinary masked attention per sequence — positions at or beyond seq_len are masked with −0.7 × float32max, then a max-shifted softmax. Simple and enormous, which is exactly why the task exists.

Cheater battery

  • single-token-decode — all seq_lens = 1, and the output is required to equal the v of the first cached token exactly (rtol 1e-4), repeated across the GQA group.

  • max-length — every sequence at full max_len.
  • softmax-saturating — q × 300.

Where RPA candidates now fail — and why it is progress

The two new failure signatures introduced by this arm:

  • 23 × max err … vs tol … at the correctness gate. RPA candidates now compile, run on the chip and produce numbers; they get the online-softmax rescale or the ragged mask slightly wrong. The ladder never got a single RPA candidate far enough to be wrong about arithmetic.
  • 12 × Incompatible shapes for broadcasting: [(N,N),(N,)] — the [1, page_size] mask against a [group, page_size] logit block. A real shape error inside the body, and the one thing the sd2 skeleton spells out that sd1 does not.

Golden truth

A float32 sequential lax.scan — the plainest possible statement of the recurrence. This is the one task where require_pallas = False: lax.associative_scan is an explicitly legal candidate strategy, and only importing recurrentgemma is banned.

Its reference_bf16 is overridden rather than defaulted, and the reason is a real trap: the gates stay float32 because they are float32 inputs by contract, and quantizing them would destroy the a → 1 adversarial vector's calibration — bf16 rounds 1 − 1e-6 to exactly 1.0, which zeroes sqrt(1 − a²) outright.

Cheater battery

  • a-to-one-long-memory — a = 1 − 1e-6 everywhere: the long-horizon float32 drift test.
  • dense-reset-boundaries — resets every 7th step; at every reset position h_t must equal x_t.
  • a-zero-passthrough — a = 0 everywhere, so h_t = x_t exactly (rtol 1e-5).

Golden truth

The oracle materializes the full float32 logits, takes the target column and subtracts the logsumexp — a formulation that needs 44.8 GB at production shape and is therefore explicitly labelled in the prompt as the correctness oracle and an invalid answer. The baseline is the interesting part: it is our own production custom_vjp tiled kernel, copied verbatim into the task module so the judge never imports skyrl. Its forward scans over token tiles and discards each tile's logits; its residual is the hidden tiles only, and its backward recomputes one tile's logits at a time.

Its reference_bf16 is also overridden: logits materialized at bf16, LSE at float32 — matching what the production kernel actually computes, so an honest bf16 candidate is not held to fp32 bitness. The gradient is checked as d/d(hidden) of sum(logprobs × cos(arange(n))), against the fp32 reference at its own calibrated tolerance.

Cheater battery

  • label-in-tail — every label placed in the last 8 vocab slots. A top-k or truncated-tail LSE approximator scores this catastrophically wrong while passing a global allclose on Gaussian inputs forever.
  • lse-saturation — hidden × 80, giving ±80 logit offsets that under- and overflow exp() without a max-shifted or online LSE.
  • 150k-vocab — n=4, h=32, v=151936: LSE accumulation error across the full production vocab width.
  • All three additionally assert logprobs ≤ 0 — a log-probability that comes out positive is not a rounding error.

Current best prompt

p4 — BASE + dialect + skeleton/example + the backward contract stated exactly. FLCE is the exception to every other lesson on this page: it exports fine at every rung and dies at the mathematics of the recompute backward, which is a thing prose can fix. Stating the formula took export failures 14 → 7 and PASS 5 → 8.

Why the seam is the wrong tool for this one kernel

On FLCE the seam lost: reference gave 50% export and 2 PASS, the seam gave 31% export and 0. The harness already owned the custom_vjp for this task, so the seam gave away less than it did elsewhere while adding a two-function return contract — (logprobs, carry) — that models got wrong 8 times with too many values to unpack (expected 2).

On a task whose plumbing is a lax.scan rather than a pallas_call, the seam's interface is a net cost. That is the same lesson as the typed skeleton, one level up: the right amount of scaffolding is a property of the task's interface width, not a rung you can add uniformly.

Best result, with its caveat

8/32 PASS at p4 — an arena record for this task — with best rewards of 0.4990 (p1) and 0.2666 (p3/p4); the all-time best is 0.7008, from the tailored scaffold that has no usable gradient. This is the one task scored against a real production kernel, and every passing candidate is slower than it. That gap is precisely what RL would be asked to close.

§4 — Where the real decisions are splash, sd1 
## Where the real decisions are

* **`bq`, and your own key chunking.** The whole key axis is resident, so how
  you consume it is entirely yours: `for j in range(kv_len // bk)` over
  bk-wide slices `k_ref[0, j*bk:(j+1)*bk, :]` (Python ints, so it unrolls), or
  one giant `[bq, kv_len]` score matrix if you think it fits. It probably does
  not: the scoped VMEM ceiling is ~32 MB per `pallas_call` and a
  `[512, 4096]` f32 score tile is 8 MB before you have made a single
  temporary of it. Going over is a compile-time
  `CompileTimeScopedVmemOom: Scoped allocation with size 36.25M and limit 32.00M`.
* **Skipping work.** A key block strictly above the diagonal contributes
  nothing to any query in this block -- `j*bk > i*bq + bq - 1` -- and you know
  both indices. Roughly half the blocks are skippable and `bq` is a Python int,
  so you can skip them at TRACE time and not emit the code at all.
* **The softmax formulation.** Online (running max, running sum, rescale the
  accumulator each block) or two-pass (find the row max, then accumulate).
  Online costs an extra `exp` and a multiply per block; two-pass reads the keys
  twice.
* **Accumulation dtype and matmul precision.** See the precision note at the end
  of the dialect list -- it is the difference between passing and failing correctness.

Part V · The machinery

What a candidate has to survive

Every candidate is graded in a forked subprocess with a wall timeout, an RLIMIT_AS cap, and the hidden seed delivered over stdin only — never argv, never env, never config. Reference modules are replaced in the child's sys.modules by poison stubs that raise on any attribute access, which catches obfuscated imports no AST scan can see.

The gate ladder, in the order the judge applies it
#GateWhereWhat it checks
1astCPU childBanned imports, banned dotted calls, and the per-task pallas_call requirement.
2poison_stub / execCPU childThe module must import and define the entrypoint without executing the kernel.
3aot_exportCPU child, no deviceThe same entrypoint must trace and serialize with jax.export at every declared shape — including the non-divisible holdout, and the adversarial shapes.
4candidate_compilejudge chipMosaic compile, under a 90 s budget enforced both between compile units and by a watchdog thread inside one.
5correctnessjudge chipFresh hidden seeds plus the adversarial vector library, against the fp32 oracle at the calibrated tolerance, on both max and q99 tail.
6determinismjudge chip5 runs, bitwise identical.
7gradientjudge chiphas_bwd tasks only — the backward against the fp32 reference at its own calibrated tolerance.
8timed_output_correctnessjudge chipInputs are regenerated on-device per timed iteration, and correctness is re-verified on an output produced by a timed invocation — this is what kills fast-garbage / slow-correct split-personality kernels and memoization.
9alljudge chipScore = geomean of per-case median latency ratios over the declared cases, noise-floor gated; the holdout case is logged but unscored.

Timing is counterbalanced and interleaved: R,C on even iterations and C,R on odd, so slow clock and thermal drift hits both legs of a pair equally and cancels in the ratio. That order alternation is not cosmetic — with a fixed R-first order, ref-vs-ref graded 1.019–1.053 and failed the arena's own 1.00 ± 2% invariant. The noise floor is the p95 of |ratio − 1| over ref-vs-ref pairs of the identical protocol, measured per chip at boot.

Open harness bugs worth carrying forward

Highest-value fix outstanding

One model-written Pallas GMM kernel halted the TPU core at Mosaic compile time and permanently killed the judge worker. The worker then failed the next 35 candidates in its own fixture setup at ~1.1 s each — silently, as if they were model failures. The affected set was contiguous, localized to work item w000091 onward, and is excluded from every number on this page. The worker has no liveness check on its device: it should detect a RuntimeUnexpectedCoreHalt, re-lease the item, and restart its jax context or exit so the supervisor replaces it. Until then, any grid can lose a whole group to one candidate — and in an RL loop that is a whole batch.

  • RPA's timing protocol. A 0.2362 noise floor makes the task untrainable at this shape no matter how good the kernel is. Needs bigger shapes, more timing pairs, or a different score — before any further prompt work.
  • Bind the real baselines, or keep saying "fallback" out loud. Four of five denominators are fallbacks. Every headline in this project is against one of them.
  • Fix the worked example before reusing it. It must demonstrate a 3-D-operand BlockSpec, or it will keep teaching rank-2 to rank-3 tasks.
